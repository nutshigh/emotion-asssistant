API 设计

App 与后端之间的 RESTful 接口。画像处理在客户端，后端只做 LLM 代理和 Prompt 编排

核心接口

方法 路径 说明
POST /api/chat 发送消息，SSE 流式返回
POST /api/chat/summarize 对话结束后，生成摘要 + 画像更新建议
GET /api/health 健康检查

核心流程详解

POST /api/chat — 发送消息（SSE 流式响应）
请求体：
{
  "message": "今天心情不太好",
  "profile": { ... },   // 客户端上传的完整画像
  "conversation_summary": "...",  // 最近对话摘要
  "recent_messages": [...]   // 最近 N 轮对话原文
}
SSE 事件流：
data: {"type":"token","content":"我"}
data: {"type":"token","content":"在听"}
data: {"type":"token","content":"..."}
// ... 逐 token 流式输出 ...
data: {"type":"done","message_id":"msg_abc123"}
POST /api/chat/summarize — 对话后分析
时机：每次对话结束（用户关闭 App 或长时间无输入）后调用
请求体：完整的本轮对话记录 + 当前画像
响应：
{
  "conversation_summary": "用户今天分享了面试受挫的经历...",
  "profile_updates": {
    "emotional_patterns": { "current_mood": "焦虑" },
    "life_context": { "ongoing_challenges": ["面试压力"] }
  },
  "new_facts": ["用户面试了字节跳动", "有一只叫汤圆的猫"]
}

设计原则

  • 后端无状态 — 不存储用户数据，画像由客户端上传、处理后返回、客户端合并存储
  • 只有 2 个核心接口 — chat（实时）+ summarize（异步），够用不堆
  • SSE 而非 WebSocket — 单向流足够，实现更简单
