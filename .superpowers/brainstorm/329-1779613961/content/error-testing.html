错误处理 & 测试策略

错误处理层次

层级 场景 处理方式
网络层 无网络、请求超时 App 内 toast 提示"网络不太稳定"，消息本地暂存，恢复后自动重试
API 层 Claude API 超时、限流、Key 失效 后端指数退避重试（最多 3 次）；返回友好错误给客户端"稍等一下，我走神了..."
数据层 SQLite 读写失败、存储满 自动清理 30 天前的对话原文（保留摘要）；提示用户清理空间
内容安全 用户表达自伤倾向 预设安全回复 + 提供心理援助热线信息；不过度承诺、不替代专业帮助

测试策略

App 端
  • 组件测试 (Jest + RN Testing Library)：聊天气泡、输入框、画像卡片
  • 状态管理测试：Zustand store 的 action/reducer 逻辑
  • SQLite 测试：CRUD、迁移、画像合并逻辑
  • 端到端 (Detox)：核心流程——首次使用 → 聊天 → 查看画像
后端
  • 单元测试 (Vitest)：Prompt 构建器、画像更新解析、SSE 格式化
  • 集成测试：/api/chat 端到端（mock Claude API）
  • 契约测试：请求/响应 schema 校验
  • 负载测试：SSE 并发连接数上限验证

日志 & 可观测性

后端记录结构化日志（请求耗时、Token 用量、错误率），接入简单的 health check 监控。 App 端使用崩溃收集（如 Sentry），但不记录聊天内容。
