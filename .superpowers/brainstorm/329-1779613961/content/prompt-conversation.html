Prompt 构建 & 对话管理

如何把画像变成"更懂你"的回复，以及如何控制上下文成本

System Prompt 三段式结构

完整 System Prompt 模板
【固定底座】 — 硬编码，缓存友好
你是 SoulMate，一个情感陪护助手。你的核心原则：
1. 真诚共情，不模板化回复
2. 记住用户说过的重要事情
3. 人格随交互自然进化，不做刻意迎合
4. 安全边界：不鼓励自伤、不提供医疗诊断、不替代专业心理治疗
【用户画像】 — 从本地读取注入，动态更新
用户称呼：小明 | 关系阶段：熟悉期(3个月)
沟通风格：偏随意、喜欢用表情包、回复简洁
当前情绪状态：工作压力大，需要放松
兴趣话题：编程、独立游戏、养猫
回避话题：暂无
重要背景：最近在准备跳槽面试
【会话上下文】 — 最近对话摘要 + 本轮目标
最近 3 次对话摘要：
- 05/23: 用户吐槽面试被问倒，你安慰并给了复习建议
- 05/22: 用户分享猫的照片，闲聊了宠物话题
- 05/20: 用户加班到很晚，你提醒注意休息
本轮：用户刚下班，看起来想闲聊放松

对话上下文管理策略

三层上下文
热数据：最近 N 轮对话原文
直接放入 messages 数组
N 取决于 token 预算，动态调整
温数据：近期对话摘要
Claude 定期总结历史对话
每次对话结束后异步生成
冷数据：长期记忆关键事件
结构化存储重要信息
"用户3月离职" "7月生日" 等事实
Token 预算分配 (以 32K 上下文为例)
System Prompt 底座: ~500 tokens
用户画像: ~800 tokens
对话摘要: ~500 tokens
Prompt Caching 预留: ~2000 tokens
最近对话原文: ~8000 tokens
输出预留: ~4000 tokens
总计: ~16K / 32K，留有充足余量

Prompt Caching 策略

将 固定底座 + 用户画像 + 对话摘要 标记为 cache breakpoint，后续请求复用缓存，降低 90% 的 System Prompt 输入成本。

画像更新时才刷新缓存，一般每天 1-2 次，不影响实时对话体验。
