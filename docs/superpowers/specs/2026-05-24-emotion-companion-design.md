# 情感陪护助手 — 设计文档

## 概述

一款 Android 情感陪护助手 App。核心特点是**人格从白板起步，随用户交互自然进化**，越用越懂用户。通过云端 LLM 提供高质量对话，用户画像完全存储在设备端保障隐私。

**目标用户**：中文用户，需要情感陪伴和日常倾诉渠道。

## 技术选型

| 层 | 技术 | 理由 |
|---|---|---|
| App | React Native (TypeScript) | 聊天类 App 生态成熟（gifted-chat），跨平台潜力，开发效率高 |
| 状态管理 | Zustand | 轻量，适合中等复杂度状态 |
| 本地存储 | SQLite (react-native-sqlite-storage) | 结构化画像 + 聊天记录 |
| 后端 | Node.js + Express (TypeScript) | 与前端统一语言，Claude SDK 最完善 |
| LLM | Claude API (Opus 4.6 / Sonnet 4.6) | 情感理解深度好，Prompt Caching 降成本 |
| 部署 | Railway / 阿里云函数计算 | 轻量部署，按量付费 |

## 架构

```
┌──────────────────────┐     ┌──────────────────────┐     ┌─────────────┐
│   React Native App   │────▶│   Node.js 后端        │────▶│  Claude API  │
│                      │◀────│   (Express + TS)      │◀────│             │
│  · 聊天 UI            │     │                      │     │             │
│  · 画像管理 (SQLite)  │     │  · API 代理           │     │  · Prompt   │
│  · SSE 流式接收       │     │  · Prompt 构建器       │     │  · Caching  │
│  · 本地存储           │     │  · 画像分析引擎        │     │  · SSE      │
└──────────────────────┘     └──────────────────────┘     └─────────────┘
```

**关键原则**：后端完全无状态。画像数据由客户端在每次请求中携带，后端处理完毕后不保留。

## 用户画像系统（核心差异化）

### 画像维度

画像以 JSON 结构存储在设备端 SQLite 中，包含六个维度：

1. **沟通风格** — 正式/随意、简洁/详细、幽默程度、emoji 使用频率
2. **情绪模式** — 常见情绪、压力源、应对方式、最佳回应策略
3. **兴趣与话题** — 高频话题及置信度
4. **生活背景** — 职业、日常节奏、重要关系、当前挑战
5. **交互偏好** — 活跃时段、平均会话时长、回复长度偏好
6. **关系状态** — 关系阶段（新建/熟悉/亲密）、回避话题、共享记忆

每个字段附带置信度（0-1），低置信度内容在 Prompt 中优先级低。

### 演化流程

1. 用户发送消息 → App 读取本地画像 + 最近对话 → 发送给后端
2. 后端将画像注入 System Prompt → 调用 Claude API → 流式返回
3. 对话结束后（用户离开或长时间无输入）→ 后端调用 summarize 接口
4. summarize 返回画像更新建议 + 对话摘要 → App 合并写入本地 SQLite

### 冷启动

- 不做问卷调查，从自然对话中学习
- 前 20-30 轮对话，System Prompt 引导助手更主动了解用户
- 影像字段逐步从低置信度累积到高置信度

### 隐私

- 画像数据仅存设备 SQLite
- 每次请求携带画像到服务端构建 Prompt，请求结束后服务端不保留
- 提供「清除画像」和「导出画像」功能
- App 端崩溃收集不记录聊天内容

## Prompt 设计

### System Prompt 三段式结构

1. **固定底座**（~500 tokens）— 角色定义、核心原则、安全边界。内容硬编码，走 Prompt Caching
2. **用户画像**（~800 tokens）— 从本地 SQLite 读取注入。更新频率低（每天 1-2 次），走 Prompt Caching
3. **会话上下文**（~500 tokens）— 最近对话摘要 + 长期记忆的关键事实

### 对话上下文三层模型

- **热数据**：最近 N 轮对话原文，直接放入 messages 数组
- **温数据**：近期对话摘要，每次对话结束后由 Claude 异步生成
- **冷数据**：长期结构化记忆（如"用户 3 月离职""7 月生日"）

### Token 预算（以 32K 上下文为例）

- System Prompt 底座：~500 tokens
- 用户画像：~800 tokens
- 对话摘要：~500 tokens
- Prompt Caching 覆盖：~2000 tokens
- 最近对话原文：~8000 tokens
- 输出预留：~4000 tokens

### Prompt Caching 策略

固定底座 + 用户画像 + 对话摘要标记为 cache breakpoint。画像更新时才刷新缓存（通常每天 1-2 次），其余请求复用缓存，节省约 90% 的 System Prompt 输入成本。

## App 界面设计

### 设计风格

温暖简洁，暖色系（米白底 + 杏色 accent + 焦糖色点缀），大圆角，宽松间距，系统默认字体。避免科技感/AI 感。

### 页面结构（底部三 Tab）

**Tab 1 — 聊天**：气泡式对话界面，暖色聊天气泡（对方杏白、自己浅橘），底部输入框 + 发送按钮。

**Tab 2 — 我们之间**：极简设计。仅展示两项数据——认识天数（大字展示）+ 累计对话次数。居中排版，花朵 emoji 装饰。

**Tab 3 — 设置**：每日问候开关、回复风格选择、清除记忆、导出数据。

## API 设计

### POST /api/chat

发送消息，SSE 流式返回 AI 回复。

请求体：
```json
{
  "message": "今天心情不太好",
  "profile": { "...完整用户画像..." },
  "conversation_summary": "最近对话摘要",
  "recent_messages": [ "...最近N轮对话原文..." ]
}
```

SSE 事件流：
```
data: {"type":"token","content":"我"}
data: {"type":"token","content":"在听"}
...
data: {"type":"done","message_id":"msg_abc123"}
```

### POST /api/chat/summarize

对话结束后调用，分析对话内容，返回摘要和画像更新建议。

请求体：完整本轮对话记录 + 当前画像。

响应：
```json
{
  "conversation_summary": "用户今天分享了面试受挫的经历...",
  "profile_updates": {
    "emotional_patterns": { "current_mood": "焦虑" },
    "life_context": { "ongoing_challenges": ["面试压力"] }
  },
  "new_facts": ["用户面试了字节跳动", "有一只叫汤圆的猫"]
}
```

## 错误处理

| 层级 | 场景 | 处理 |
|------|------|------|
| 网络层 | 无网络、超时 | Toast 提示"网络不太稳定"，消息暂存本地，恢复后重试 |
| API 层 | Claude API 超时、限流 | 后端指数退避重试（最多 3 次），返回友好文案 |
| 数据层 | SQLite 满 | 自动清理 30 天前对话原文（保留摘要） |
| 内容安全 | 用户表达自伤倾向 | 安全回复模板 + 心理援助热线信息，不替代专业帮助 |
